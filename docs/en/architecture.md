# Architecture and interface

English version of [architettura.md](../architettura.md). Where the two disagree, the
Italian file is the reference.

## Folders
- `src/`: front end of the island and of the settings window (TypeScript, no
  framework, Canvas 2D).
  - `src/character/`: the characters, chosen with `theme.character`. The contract
    and registry are in `character.ts`, the list in `roster.ts`.
  - `src/island/`: state machine (`fsm.ts`), agent hooks (`hooks.ts`),
    integrations, context, the agent's plan (`plan.ts`), risk warnings (`risk.ts`).
  - `src/views/`: every view.
  - `src/settings/`: the settings window.
  - `src/core/`: state (`state.ts`), markdown, sounds, calculator, layout, the
    3CX softphone (`softphone.ts`), translations (`i18n.ts`).
- `src-tauri/`: Rust backend (Tauri 2): window, named pipe, APIs, pollers,
  Credential Manager, notification area, NSIS hooks.
- `hook/`: `easyisland-hook.exe`, the hook relay (see
  [agents-and-chat.md](agents-and-chat.md)).
- `dev/`: browser previews (`scenes.ts`, `*-preview.html`).
- `scripts/`:
  - `gen-icons.mjs`: the app icon, drawn in code (three pills forming an "E", from
    violet to light blue); also copies it to `site/media/icon.png`.
  - `gen-brands.mjs`: brand logos from `brand/` into `src/views/brands.ts`.
  - `pack.mjs`: copies the installer to `release/`.
  - `screenshots.mjs`: regenerates the README screenshots.
- `screenshots/`: the README images; they are the current visual reference.
- `brand/`: source SVGs of the logos. The app never reads this folder.
- `site/`: the static homepage published on GitHub Pages.

## Characters
- Goccia (`drop.ts`, the default since 0.6.4) and Slime (`slime.ts`) are "soft"
  characters: outline, shading and eyes, everything else shared. EasyTech is the 3D
  cube (`cube.ts`).
- `engine.ts`, `greeting.ts` and `src/upload/canvas.ts` draw by asking for
  `character()`, never a character by name.
- **New soft character:** one file exporting a `SoftCharacter` and one line in
  `roster.ts`. Try it with `dev/character-preview.html?character=<id>` and
  `dev/upload-preview.html?character=<id>`.
- **Gecko** (`gecko.ts`), **Flame** (`flame.ts`), **Rock, Magma, Stone**
  (`blobs.ts`) and **Leaf** (`leaf.ts`) are traced from reference drawings measured
  pixel by pixel: the outline is a table of radii joined by a curve, and the colour
  areas are stored as curves generated by a measuring script, not by hand. New
  characters are only made starting from a drawing.
- The Flame moves by itself (`animated: true` in the contract): it keeps the frame
  loop alive in `engine.busy`, at 30 fps, and stops when the island is hidden like
  every other animation.
- On the Overview the character has the theme colour and shows the most urgent state
  of all (`URGENCY` in `state.ts`: permission > question > error > limit > work > …
  > rest).
- **Character reactions** (Settings → Notifications, `settings.reactions`): for each
  situation `show`, `quiet` (state on the character, no sound or opening) or `off`.
  Permissions and questions cannot be quietened: the agent is waiting.
- **Weather sky:** `src/character/weather.ts` draws sun, moon, clouds, fog, rain,
  snow or storm behind the head. Only rain and snow move, and the loop stops anyway
  when the island is hidden.

## Island, layout and position
- **Quick answers with the island closed** (`src/views/strip.ts`, `compactStrip`:
  `right`, `left`, `off`): a strip next to the compact character with a line of text
  and, when something is waiting, its buttons — a simple permission (Deny / Allow),
  a 3CX call (Answer / Decline, Mute / Hang up), a request that needs the island, a
  working session. While something waits, the compact view does not hide.
- **App bar** (`appBar`): in the same strip, only the user's quick actions tied to
  the program in the foreground ("In the bar with", `*` = all), in their order.
  Nothing built in. Actions can be of any type, including **Keys** (`keys.rs`:
  shortcuts, quoted text, "wait N") sent only to the window that was in the
  foreground.
- Geometry is in `src/core/layout.ts` (`anchoredOrigin`, `glueFor`, `cornerRadii`,
  `collapsedBox`, `compactSize`); on the Rust side `island.rs` (`apply_geometry`,
  `placement_from_drop`).
- **Secondary screens:** dropping the character on another screen sets `screen` to
  `monitor:<name>`. Dragging is anchored to the cursor in physical pixels.
- **Open island size:** `islandWidth` and `islandHeight` go up to the screen's work
  area; the window is at least 720×560 and only grows when the user changes the
  size, never with a view, so an animation is never cut.
- **Content during the animation:** views are laid out at the final width of the
  open island (`--view-w`), not the animated one, so text does not reflow on every
  frame.
- **Right-click menus:** on the resting character, the notification area menu; in
  the open island, `contextItems` in `island.ts` and `src/views/ctxmenu.ts` replace
  WebView2's menu, depending on what is under the mouse. Nothing in them deletes,
  sends or runs without its own confirmation.
- **Where it opens (`islandPlace`):** where the character is, or centred at the top,
  middle or bottom of the work area.
- New scrolling lists use `max-height: calc(Npx + var(--extra-h, 0px))` so they grow
  with the island; a view's `fitHeight` is always measured with `--extra-h` at 0,
  otherwise the island jumps between two heights.

## Views, menu and top bar
- **Open island layout:** a top bar (`buildHeader` in `views.ts`) with the
  character's speech bubble, the single search field and the buttons; on the left the
  **menu** (`src/views/rail.ts`) with the character on top and then Overview, Agents,
  Chat, Actions, Files and screen and the active integrations; the views on the
  right. There is no "edit mode" in the island: what is shown and how is chosen only
  in Settings.
- **Overview** (`renderSummary` in `views.ts`): a tile per integration and agent with
  its last line and a large faded logo in the corner; tiles reorder by dragging, in
  the same order as the menu.
- Every card has a coloured glow at the bottom (`.card.wash`, `--wash`): the tab's
  own colour on integrations, indigo on the chat and the Overview, amber on Actions,
  green on Files and screen.
- Brand logos: SVG in `brand/`, a line in the map of `scripts/gen-brands.mjs`, then
  `node scripts/gen-brands.mjs` writes `src/views/brands.ts`. They are used through
  `brandOrDot` and `markIcon` (`dom.ts`).
- **📌 Keep open** turns the open island into a normal window (taskbar icon, Alt+Tab,
  no longer always on top; `set_app_mode` in `island.rs`).
- **Search field** (`src/views/search.ts`, `searchBar`): finds integrations,
  sessions, ⚡ actions and Start menu programs; the last two entries are always "Ask
  the chat" (`Ctrl+Enter`) and "Search with Google" (`Alt+Enter`). Clicking a menu
  entry while typing closes and clears it. It takes the keyboard only when the user
  opened the island, never for an alert.
- Markdown in answers: `src/core/markdown.ts` (DOM, never `innerHTML`).

## Robustness
In release Rust has `panic = "abort"`: a panic in any thread closes the app. The
defences to keep when adding code:
- **Rust:** no `&s[a..b]` or `[i]` on text or data from outside (network, files,
  agents): use `s.get(a..b)?`. `clamp(min, max)` only with `min <= max` guaranteed.
  No `Instant - Duration`.
- **Synchronous Tauri commands** run on the main thread: slow work (file copies,
  network, processes) goes `async` with `spawn_blocking`.
- **User files:** `settings::write_atomic` (temporary file, `sync_all`, rename).
  `settings.json` keeps a backup copy; an unreadable file is set aside, never
  overwritten with defaults.
- **Island frame:** every part goes through `guard` in `island.ts`: an exception is
  logged once and the loop goes on. A card that fails to draw is replaced by a
  fallback (`safeCard`).
- **Incoming data:** agent events go through `sanitize` (`hooks.ts`); an error inside
  a `PermissionRequest` sends the question back to the terminal, so the agent never
  waits for nothing. Integration data is normalised before drawing.

## Settings
- Pages are in `pages()` of `src/settings/main.ts`. `commit()` only saves;
  `render()` rebuilds the page and is called only when the structure changes.
- While the Settings window is active it stays above the island, and returns to
  normal when another window is chosen.

## Language
- Italian or English (`settings.language`: `""` = like Windows, `"it"`, `"en"`). One
  dictionary, `src/i18n/en.json`, keyed by the Italian text, used by TypeScript
  (`src/core/i18n.ts`) and Rust (`src-tauri/src/i18n.rs`).
- `scripts/check-i18n.mjs` (part of `npm run build`) fails if a string has no English
  translation.

## Sounds
- The 28 sounds are synthesised in `src/core/synth.ts` and played by
  `src/core/sound.ts`; listen to them in `dev/sounds-preview.html`. The only
  exception is the 3CX "This PC" ringtone, which can be a file chosen by the user.

## Performance
- No animation frames and ~0 % CPU when the island is withdrawn. Pollers run three
  times less often on battery and stop while EasyIsland is paused.
