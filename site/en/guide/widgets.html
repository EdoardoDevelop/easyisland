Connecting services

Widgets

Repeatable checks without code: sites, certificates, domains, servers, ports, services, calendars, APIs.

Settings → Widgets adds checks you can repeat as many times as you like (a site per client, a server per office…). Unlike integrations, which are one per service, widgets are probes.

KindWhat it checks
CalendarUpcoming appointments from an ICS link (Google Calendar, Outlook.com, iCloud), no sign-in; alerts a few minutes before. The link is secret and lives in the Credential Manager
Domain expiryDays until one or more domains expire (RDAP, or WHOIS for registries like .it)
WebsiteThat an address answers (2xx/3xx or the status you set) and how fast
HTTPS certificateDays until expiry: orange under 30, red under 7 or expired
PingThat a host answers (no administrator rights)
TCP portThat a port is open (e.g. 3389, 22, 443)
Windows serviceThat a local service is running (e.g. Spooler)
JSON APIAny API: the fields to show (a path like data.items[0].status) and an alert rule (e.g. open > 10); secret headers in the Credential Manager
  • ▶ tests a widget right away.
  • When a check goes from OK to a problem: dot in the menu, sound, island showing up (following the profile's notifications). A new error shows only if it repeats 15 seconds later, and after standby checks wait for the network to come back.
  • Rarer on battery, stopped when paused.
  • Widgets belong to the profile and can start an automation.

Tip: for a single service with more data (an API with lists, alerts and actions) a custom integration with a data source is better.
